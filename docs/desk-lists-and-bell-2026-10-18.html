Summary

The player directory, the registration desk and each of the import review tabs show 50 rows at a time; changing the search, filter or tab returns to page one in the same render; a list that fits one page shows no pager; and print, the draw groups and the desk's player search are deliberately left unpaged. 03

The bell, and why it does not lie

The bell exists because the draw validator cannot see everything the desk needs to know: entries still needing review, a cut-off approaching, and the draw's own group problems. The design keeps one rule about each kind of problem:

  • Draw rules stay in the app. validateDraw is still the only place those rules live, so the bell and the Draw screen's Issues panel cannot disagree. Nothing about the draw was copied into SQL.
  • Two sources, merged and de-duplicated. Live issues win over a stored row for the same problem, because the live issue clears itself. One problem shows once, so the badge cannot double-count.
  • Read state only quiets info. The badge counts unresolved blocking and warning items whatever their read state; marking a notice read can never hide something that stops publishing. "Dismiss notices" says how many info notices it will quiet, and says plainly that blocking and warning items stay.
  • No polling. A debounced signature of the data that can create or clear an alert triggers one check after a burst of changes. There is no timer.
  • No false all-clear. The panel only says "All clear" after a check that succeeded and found nothing. While a check runs, or after one fails, it says so and keeps the last good list underneath the error.
Demo mode: with no Supabase environment the bell still works from the live issues alone, which is what the desk sees before the project is connected.

The live sync check

Against the live project, signed in as the real desk account and the owner account through the app's own anon key and RLS. A disposable player and a registration were created for the check and removed afterwards.

  1. An alert appears. A registration with status needs_review was created; sync_notifications returned 1 and the loader showed a warning, unread.
  2. Fixing the cause clears it. The status was corrected; the next sync returned 0, the open list was empty, and the stored row carried resolved_at.
  3. An info notice can be dismissed. The event cut-off was moved inside the seven-day window temporarily; the sync created a cutoff_soon info notice, and mark_notifications_read returned 1.
  4. Read state survives a reload. A fresh session for the same account still showed the notice as read. A second dismiss returned 0, so the call is idempotent. The owner's own read state stayed false, because read state is per user.
  5. RLS holds. The anonymous key read 0 notifications.
  6. Cleanup. The cut-off was restored and every test row was deleted; the project is back to 0 players, 0 registrations and 0 notifications from this check.
No RLS or grant change was needed. Both roles could call both functions and see the rows through the existing policies.

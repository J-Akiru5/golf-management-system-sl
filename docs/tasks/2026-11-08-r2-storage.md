# R2 storage for media and documents

Date: 8 November 2026. Branch: `feat/issue-187-r2-storage`, based on `origin/develop` at `461cdab`.
Task: T-0009 / issue #187.

## Objective

Give event logos, course maps and generated PDFs one storage path beside the existing scorecard
scan: validated presigned uploads, private or explicit public reads, deletion, a staff-guarded
presign route and a clear owner setup runbook. The live scorecard scan contract does not change.

## What changed

- `src/lib/storage/` is the reusable service: configuration parsing, upload rules, presigned PUT and
  GET, public and signed read selection, and delete.
- `src/app/api/storage/presign` is the staff-only route. It authenticates with the Supabase server
  client, checks the club role and signs a PUT for the caller's club.
- `src/app/api/scoring/scan/presign/route.ts` now uses the shared presign client. Its request body,
  key format, response shape, 12 MB image limit and demo path are unchanged.
- `src/lib/scoring/scan/r2.ts` keeps the scorecard helpers on top of the shared client and remains
  image-only, so PDFs cannot enter the scan path.
- `.env.example` documents the R2 variable names, including `R2_PUBLIC_URL`. It carries no values.

## Storage API

Configuration:

```ts
parseStorageConfig(env)       // returns null unless all four required names are set
getStorageConfig()            // same, from process.env
requireStorageConfig()        // throws StorageNotConfiguredError
isStorageConfigured()         // boolean
```

Required names: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`.
Optional names: `R2_ENDPOINT` (defaults to `https://<account>.r2.cloudflarestorage.com`) and
`R2_PUBLIC_URL` (a public custom domain). The endpoint and public URL are trimmed of trailing
slashes.

Upload rules:

| Type | MIME | Extension | Cap |
| --- | --- | --- | --- |
| JPEG | `image/jpeg` | `jpg` | 5 MB |
| PNG | `image/png` | `png` | 5 MB |
| WebP | `image/webp` | `webp` | 5 MB |
| PDF | `application/pdf` | `pdf` | 20 MB |

The caps are `IMAGE_MAX_BYTES` and `DOCUMENT_MAX_BYTES` in `src/lib/storage/validation.ts`.
`validateUpload(mime, bytes)` rejects an unsupported type, a size that is not a positive integer, or
an oversized payload with a typed error before any URL is signed.

Functions:

```ts
createObjectKey(clubId, useCase, mime)          // <club-id>/r2/<logos|course-maps|documents>/<uuid>.<ext>
createPresignedUpload(key, mime, options)       // { key, method, uploadUrl, headers, expiresIn }
createPresignedDownload(key, expiresIn)         // { key, method, url, expiresIn }
publicObjectUrl(key)                            // public URL, or null when R2_PUBLIC_URL is empty
objectReadUrl(key, { visibility, expiresIn })   // explicit public or signed selection
deleteObject(key)                               // one signed DELETE request
```

The default expiry is 900 seconds. Signed expiries are limited to 7 days. Keys are relative object
paths; empty, absolute, traversal and control-character keys are rejected.

## Staff presign route

`POST /api/storage/presign` accepts:

```json
{ "useCase": "logo", "mime": "image/png", "bytes": 12345 }
```

`useCase` is one of `logo`, `course-map` or `document`. The caller must be signed in with an owner,
organizer or desk role. The club comes from the membership, never from the request body. Success
returns only:

```json
{ "key": "...", "uploadUrl": "...", "headers": { "Content-Type": "image/png" }, "expiresIn": 900 }
```

Errors use the usual `{ "ok": false, "message": "..." }` shape. No access key, secret, bucket token
or signed URL is returned except the upload URL itself.

## Owner setup runbook

These are owner actions. The branch does not create a bucket, token, CORS rule or domain.

### 1. Bucket

1. In the Cloudflare dashboard open **R2 Object Storage** and create a bucket, for example
   `golf-media`. Choose the location hint that suits the club.
2. Leave public access off. The bucket stays private; the app reads through signed URLs.
3. Keep the bucket name for `R2_BUCKET`. The account id is on the R2 overview page and is not the
   bucket name.

### 2. API token

1. Open **R2 Object Storage > Manage R2 API Tokens > Create API token**.
2. Grant **Object Read & Write** and scope the token to this bucket only. Do not grant access to all
   buckets.
3. Copy the **Access Key ID** and **Secret Access Key** when they are shown. The secret is shown
   once. Store it in the deployment environment, never in the repository, a document or a chat.
4. Put the values in `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`. The account id goes in
   `R2_ACCOUNT_ID`.

### 3. CORS

The browser uploads directly with a signed PUT, so the bucket needs a CORS rule for the app origins
you actually use:

- Allowed origins: the local development origin and the deployed staff origin, for example
  `http://localhost:3000`, `http://localhost:3001`, `https://golf.syntaxure.dev` and any new staff
  origin.
- Allowed methods: `PUT` and `GET`.
- Allowed headers: `Content-Type`.
- Exposed headers: `ETag`.
- Max age: 3600 seconds or the Cloudflare default.

Delete runs on the server and does not need a browser CORS method. CORS is not authentication; the
signed URL is the authorization.

### 4. Custom domain

This step is optional. Without it every read is a signed URL.

1. Open the bucket **Settings > Public access > Custom domains** and connect a domain, for example
   `media.example.com`.
2. Set `R2_PUBLIC_URL` to that origin, without a trailing slash.
3. Only objects the code explicitly marks public use this domain. A public custom domain does not
   make the bucket private by accident; the bucket stays private and the domain serves only objects
   the caller chooses to expose.
4. Leave `R2_PUBLIC_URL` empty to keep every read signed.

### 5. Environment variables

Set these in local `.env.local` and in the Vercel project environment. Names only:

```text
R2_ACCOUNT_ID
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
R2_BUCKET
R2_ENDPOINT            optional; defaults to https://<account>.r2.cloudflarestorage.com
R2_PUBLIC_URL          optional; public custom domain
```

No value belongs in `.env.example`, a commit, a log line or a browser response.

### 6. Verify without deploying

Run this locally after the environment is set:

1. `pnpm dev` and sign in as an owner, organizer or desk user.
2. In the browser devtools console on the app origin, request a presign:

   ```js
   const response = await fetch("/api/storage/presign", {
     method: "POST",
     headers: { "Content-Type": "application/json" },
     body: JSON.stringify({ useCase: "logo", mime: "image/png", bytes: 1024 }),
   });
   console.log(await response.json());
   ```

   Expect a 200 with only `key`, `uploadUrl`, `headers` and `expiresIn`. The response must not
   contain an access key or secret.
3. PUT a small PNG to `uploadUrl` with the returned headers. Expect a successful response, then see
   the object under the club prefix in the R2 dashboard.
4. Open the object URL without a signature and confirm it is refused. The bucket is private.
5. Check the refusals: `mime: "image/gif"` returns 400, `bytes: 6 * 1024 * 1024` returns 400 for an
   image, and the same request in a signed-out window returns 401.
6. Run a scorecard scan in the desk and confirm the photo upload and extract path still work.

Nothing above needs a deployment, a Vercel preview or a production change.

## Security boundaries

- Credentials stay server-side. The route returns the signed upload URL and headers only.
- The route authenticates the Supabase user and checks the club role before signing.
- Object keys are scoped to the caller's club and one of the three use cases.
- The bucket remains private. A public URL requires `R2_PUBLIC_URL` and an explicit public choice in
  the calling code.
- Validation happens before signing. The byte count is the size the client declares; a presigned
  PUT cannot pin the final object length by itself. For a hard size guarantee, add a post-upload
  check or a separate completion step later.
- No secret or signed URL is logged. Error messages carry a reason, not a credential.
- CORS controls which browser origins can call the bucket; it does not grant access without a signed
  URL.

## Out of scope

- **Player avatars.** They need a new auth and RLS rule, plus the photo consent rules in the player
  profile. No avatar upload path is wired here.
- **Supabase bucket changes.** The existing `player-photos-public` and `event-logos` buckets and
  their policies are untouched. This task adds an R2 path, not a Supabase storage change.
- Creating a Cloudflare account, bucket, token, CORS rule or custom domain.
- A migration, a deployment, a Vercel configuration change or an R2 lifecycle rule.
- CSV documents. The shared allow-list covers images and PDF.
